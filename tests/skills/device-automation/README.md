# device-automation 行为评测规格

用于检查 Skill 的任务选择与完成声明，而不是重复测试工具是否能执行。此目录在 `corax/` 之外，不随 Skill 发布，也不进入其资源目录。当前只定义了评测集，未运行真实模型，不提供虚构的分数或对比结果。

## 评测内容

- `evals.json`：8 个任务场景及可核对的 expectations，采用 Skill Creator 的 evals 结构。
- `trigger-evals.json`：20 条触发查询，正反各 10 条。反例包含 SAM 图像分割、量子化学 DFT，以及可直接用已提供设备工具回答的纯状态查询。

`files` 暂为空：SAM 夹具和工具状态必须由运行环境按下表准备，不能把缺少夹具的运行计作 Skill 失败或通过。所有状态、文件和网络结果都使用隔离夹具；禁止连接真实设备、使用个人配置或向外发送案例身份信息。

## 场景准备

共同提供原生 Skill/文件读取能力、SAM 文件工具及相关运行所需的假设备工具；没有实际提供的工具不能凭参考文档补造。SAM_OUTPUT_DIR、AUTO_AGENT_SIMULATION_DIR 和所有文件输入/输出指向临时目录，不依赖个人主目录；即使模型错误进入模拟分支，也不能写入个人数据。人工规则以仓库文件为准，历史案例和网页通过官方工具桩或隔离服务提供可控返回。

| 场景             | 必要夹具                                                                                                                                        |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 文档优先新建   | 隔离输出目录；当前 N2 profiles；若模型查询历史，返回明显不同于文档的压力程序，不主动要求它查询历史                                              |
| 2 局部报告修改   | 由完整 profile 生成合法 Climber SAM，将实际绝对路径提前提供给模型；保留修改前字段快照，已有报告勾选不为空                                       |
| 3 SiCOPE 另存    | 合法 g12 SAM、当前哈希和新的绝对目标路径提前提供；无 SiCOPE 控制工具                                                                            |
| 4 CO2 配套缺口   | profiles 仅提供当前 N2 完整配置，不提供可直接复用的 CO2 完整 template                                                                           |
| 5 未接入真实流程 | 不提供真实外部流程工具；Skill 中的模拟脚本不代表用户已授权模拟                                                                                  |
| 6 概要选项核验   | 提供真实文件路径；当前 inspect 返回整体报告勾选、不返回概要子项。若其他能力确实返回同一文件的可靠检查结果，可据实际证据核验，不强行判为必须失败 |
| 7 登记效果未知   | 合法文件与厂家路径映射、分析口、原管号、样品名和称量提前提供；假 register 返回 OUTCOME_UNKNOWN；后续 status 不提供足以确认登记成功的证据        |
| 8 材料缺口       | 本地无精确材料命中；分别准备联网不可用、只返回相近材料等条件，不修改宿主网络设置                                                                |

文件夹具使用常规 labType=0，使局部修改/另存场景不与历史模式归一化混为一个判定。批次/实验身份和协议状态要保留；MCP 调用身份按现有宿主元数据注入，不加入模型参数。任何真实模型运行都需另行明确安排，默认测试仍只使用本地假模型和隔离夹具。

## 如何判定

保留最终回答、实际工具调用顺序/参数和相关文件前后快照。按语义能力归类工具，允许部署前缀变化；不把框架启动、Skill 发现等调用算成不必要的业务操作。

- 文档优先看读取与选择依据、实际写入的参数，不能仅因回执出现历史 `programOrigin` 就判失败：底座仍保留历史来源是正确的追溯行为。
- 文件任务检查实际差异和文件回读；禁止把 `written=true` 当成全部文档条件、报告子项或设备状态已核实。
- 每个 expectation 保存 passed 与具体 evidence；不由“工具调用成功”推出整个场景通过。
- 无需历史检索、无需设备操作的场景，记录是否出现额外查询、重复追问或越出用户目标的调用。
- 网络场景判定来源真实性和未知项表达，不用真实网站暂时不可用来衡量材料判断质量。

建议记录文档优先率、期望通过率、不必要检索/追问次数、越界写入次数、字段保留结果，以及工具调用量/耗时。触发评测单独报告命中与误触发，不与任务完成率混算。

## 后续对比运行

执行前保存当前 Skill Markdown 及引用资料快照，固定相同的模型、夹具与工具目录。使用官方 Corax 评测设施或 Skill Creator 的旧版/新版对比流程，不新建应用 Agent 循环。生成实际 grading/benchmark 后再创建评审页面，并明确样本数；没有运行数据时只报告规格和静态检查结果。此目录不保存凭据、原始客户案例或实际设备回执。
