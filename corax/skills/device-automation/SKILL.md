# 测样规划与设备任务编排

## 仪器名称与能力边界

- Climber 的研发别称是 G5，SiCOPE 的研发别称是 G12；它们不是四款仪器。面向用户优先使用 Climber、SiCOPE，引用研发资料或解释文件格式时可附上 G5、G12。
- SAM 参数沿用文件标识：Climber 使用 `product=g5`，SiCOPE 使用 `product=g12`。别称对应关系不改变各自的软件版本、枚举和完整配置，历史资料中的产品别称、版本与文件标识仍需保留，案例身份信息按脱敏资料呈现。
- SAM 文件处理与仪器控制分开判断。当前 `sam_file` 支持两款产品的文件处理，已接入的厂家控制能力仅为 Climber；处理 SiCOPE 文件不代表已接入 SiCOPE 控制，不把 SiCOPE 任务下发给 Climber 工具。

本文区分四类“模板”：**文档模板**是人工定义的测量方案；**profile** 是产品/版本的完整文件底座；**历史 SAM** 是过往文件证据；**流程模板**属于外部自动化系统。选择 profile 或查到历史案例，不等于重新选定本次文档模板。

## 先按当前目标路由

从用户本次目标和已知上下文选择一条入口，先读对应资料，不把所有任务套进完整测样流程。

加载本技能后，按需通过宿主提供的文件读取能力阅读相对路径下的 references。SAM 实现和完整配置由 Climber MCP 提供，技能保留方法和工作流；安装技能不会自动接入设备或注册工具。

当前工具目录提供 SAM 能力时，直接传入操作名与参数对象，由 MCP 服务处理，不另行寻找解释器、修改 PATH 或安装运行时。文件路径是 MCP 执行宿主的绝对路径，复用返回的真实路径；跨机厂家访问仍按部署映射核对。SAM 文件能力不要求厂家连接，登记/启动仍需当前已配置的设备工具。调用形式见 SAM 参考文档。

用户已指定方法、文件或操作时，直接进入对应入口；不要重新推荐方案或研究脚本源码。只缺分析口和原管号就问这两项，不要求重填已确认的名称、质量、方法、版本或路径。只有入口确实无法从上下文判断时才询问控制对象。

选择分支依据用户要取得的结果，而不是逐个展开句子中的专业词汇。支持范围、方法定义、登记缺项与当前就绪是不同问题；只在返回结果留下具体未答问题时扩展到另一分支。

## 文档优先选择模板

新方案先按 [选择规则](./references/materials/选择规则.md) 选出文档模板，再按 [模板定义](./references/materials/模板定义.md) 整理参数。用户已确认条件保留，冲突明确说明；文档优先于历史 SAM、profile 默认程序和网络推荐。文档已覆盖时，不要求历史案例命中。证据取舍见 [资料查证](./references/wiki.md)，参数落地与核验范围见 [SAM 写入](./references/sam-create.md)。

用户明确指定某份文件进行检查、局部修改、另存或复现时，按该目标处理并保留未要求改动的字段；不额外用推荐模板重写既有文件。

## 复用输入，向前完成任务

- 材料咨询只为实际资料缺口补查历史或公开来源，并区分同材料依据、相近材料参考和推断；没有取得的证据保持未知。
- 使用当前环境提供的资料读取、知识检索、SAM文件及设备 MCP 能力。文件准备和设备查询/登记/启动分别使用实际工具目录中的对应能力；连接缺失时说明缺失能力，不改走直控脚本。安装技能不代表设备连接，模拟响应不代表真实测量。
- 支持新建模板、修改模板和另存为。文档已选定方案时，以内置完整配置为文件底座并显式写入文档参数，不要求用户另外寻找历史 SAM、完整 JSON 或内置配置已包含的软件版本；缺少样品名或称量时可先保存待填模板，依据 pendingInputs 说明缺项。
- 复用工具实际返回的 file.path；未指定位置时用脚本默认输出目录。仅在厂家访问路径或跨机映射确实缺失时询问对应条件，不把提供现成文件当作用户前置任务。
- 修改前核对文件哈希；报告选择用 modify 的顶层 reportTypes，仅切换 selected 并保留完整 options。另存为保留源文件，新建使用独立身份与实验前配置；不能用重建文件替代用户要求的原地修改。
- 批次/实验标识未指定时生成本次唯一标识，已有标识原样保留；物理分析口、原管号及实际称量按确认值使用。资料推荐、用户输入、文件事实和设备回执分别解释，不编造科学参数或仪器状态。
- 自动化流程与单仪器控制是独立入口。不要同时绕过流程直接启动其中的仪器。咨询或只读查询不授权写入；已明确授权且条件齐备的任务按依赖顺序完成，不逐步重复索取同一授权。
- 本技能提供流程指导，不负责后台计时、长期轮询和断点恢复。只有环境实际提供了持久化流程能力时才承诺后台执行；外部自动化系统拥有整套流程时，只提交和跟踪它，不拆开重复调度内部仪器。

## 只追查具体缺口

返回结果足以回答问题时停止扩展。能力不匹配、参数错误、文件变化、服务失败或效果未知时，按 [诊断与恢复](./references/recovery.md) 处理实际错误，保留原任务和标识。不要用更换编号、参数或运行时重复未知写入，也不把服务查询失败当作仪器物理状态。

内置资料提供推荐原文和历史配置证据；可执行文件配置由 SAM 接口处理。用户 LLM Wiki 是独立的文本知识库，不自动替代这些原文。BET、BJH、DFT 不可互换；检索相似、文件写入成功、命令受理、实际运行、设备完成和报告可用是不同事实。关键方案项未解决时标为 **模板推荐草案——参数尚未确认，不可下发运行**。

## 面向用户完成回复

使用中文简洁说明与当前问题有关的结论、实际执行结果和必要的下一步。测样以样品、测试目标、仪器和结果为主线；模板准备是内部步骤。用户询问或具体阻塞需要时再解释协议、文件和脚本细节，不在每次回复中展开完整参数表或通用前提清单。

仅生成或修改文件时，在返回文件路径、哈希及与本次目标相关的已核验项后结束；有未覆盖检查或待确认项时明确指出，不顺带查询设备、登记或启动。用户要求运行时，才依据对应设备能力和当前回执继续。
