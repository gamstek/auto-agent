# 材料查证、Wiki 与公开资料检索

本技能包含人工维护的 [选择规则](./materials/选择规则.md)、[模板定义](./materials/模板定义.md)，并按需使用 Agent 通用 Wiki 查询历史证据或用户知识。规则是 Skill 指导，Wiki 是 Agent 的基础能力，不属于 Climber。预置历史资料不通过用户导入流程更新。

历史数据资产随本技能保存在 assets/library.sqlite，由宿主绑定到 Wiki 的 reference 集合；使用 Wiki 检索和引用，不直接读取数据库正文或提交 SQL。

## 按问题查阅

1. 材料、预处理和模板匹配先读选择规则；注气、压力段、平衡和报告设置再读模板定义。通过原生 Skill 资源读取这两份指导，不调用 guidance 操作。
2. 需要比较历史实际配置时，通过 Wiki 的 reference 集合 search/read；按 catalog 实际返回的 filterKeys 和已确认条件过滤元数据。
3. 用户提供的知识在 knowledge 集合。保留两种资料的归属，使用搜索实际返回的 reference 读取固定版本证据，保留来源、哈希和字段路径。实际工具名称以宿主为准。

## 新方案的模板依据优先级

先复用用户已确认的条件，再以两份人工文档作为推荐依据：由《选择规则》确定材料/需求匹配与模板名称，由《模板定义》确定该模板的采集和报告设置。文档明确的条目优先于历史 SAM、案例检索结果、内置历史程序和网络推荐；冲突应明确指出，不把不同来源混成一个“推荐模板”。用户条件与文档不一致时保留用户条件并列明差异，不擅自改变目标。

文档已有推荐，不需要先搜索同材料历史 SAM，也不因历史库没有命中就停止。只有用户要做历史对比、文档引用了某一案例，或存在文档未覆盖的具体参数/适用性问题时，才有针对性地查历史证据。历史 SAM 更完整、更接近某材料或附带更多报告，不构成覆盖人工文档的理由；历史样品身份、称量、设备状态也不是本次默认值。

文档明确规定“未匹配”“待确认”或需人工确认的项，保持该状态；查到相近历史或网络案例不能自动取消这类确认要求，也不能据此回退到文档禁止使用的默认模板。

profiles 的底座来源不是推荐来源；文件参数落地和检查范围见 [SAM 写入](./sam-create.md)。说明方案时引用文档名、模板名和相关章节，历史或网络信息单独标为补充来源。对用户指定文件的检查、局部修改、另存或复现，遵循该文件目标。

工具名称以宿主实际提供的目录为准；Wiki 不接受 SQL、数据库路径或资料包导入。不要为了得到结果放宽已经确认的温度、气体或产品条件。

## 查询与分页

历史配置搜索示例：

```json
{
  "action": "search",
  "collection": "reference",
  "query": "BET",
  "filters": { "sam.product": "g5" },
  "limit": 3
}
```

读取调用为 `{"action":"read","collection":"reference","reference":搜索返回的reference}`，集合和引用必须对应并原样使用；不接受任意本地路径或自己构造的 ID。

- reference 绑定内置资料版本与文档，不编辑其标识；资料版本变化时重新搜索。
- read 通过 offset/limit 和 nextOffset 连续读取证据单元；Skill 规则按资源读取结果的分页继续阅读。
- 搜索也使用 nextOffset 翻页。snippetTruncated 表示摘要不完整，不能把摘要当作完整模板。
- sourceVerified=false 表示读取已索引版本，没有再次核验当前外部原件。索引中的路径不等于厂家当前可读的 SAM 文件路径。
- 案例名称、原始路径和样品身份信息已在数据源脱敏；`case-…` 是资料编号，`[已脱敏]` 不是新任务的样品名称或 UUID。材料类别、科学参数和原文件哈希仍保留，不尝试从哈希还原身份信息。

## 本地材料资料不足时，继续公开检索

适用于材料特性咨询、测样可行性或材料/方法方案：先判断人工文档是否已覆盖本次模板选择；已覆盖时按文档继续，不因历史案例无命中额外研究另一套模板。材料特性或适用性仍有缺口时，继续查证，不以“数据库没模板”结束回答。本地无命中不等于材料不存在或不能测量；反过来，网络上查到材料也不等于找到了完整可执行模板。单纯检查指定文件、查询设备状态或核对已知配置目录时，仍按对应入口处理，不附带无关材料研究。

### 先核对材料，再找来源

1. 复用已知的材料名称、英文名、别名、公开牌号、组成与形态，以及用户的测量目标。仅对会改变材料判断的歧义询问一个关键缺项，不重新索取已确认信息。
2. 本地先以材料本名或别名查询，再查所属材料类别和相关测量方法；不要把材料、用途、品牌和方法全拼成一个过窄查询。产品等已确认约束保留，相近类别结果明确标为参考，不冒充同材料命中。
3. 本地仍不足时，通过当前工具目录实际提供的网页搜索能力检索，再打开相关来源正文核验。没有搜索工具但有网页读取能力时，可读取公开搜索页面或公开文献索引来发现候选来源，例如 `https://www.bing.com/search?q=URL编码后的关键词`，或 `https://api.crossref.org/works?query.bibliographic=URL编码后的关键词&rows=5`。检索词用材料公开名称/别名及本次关心的性质或方法，不用脱敏案例编号反查客户或样品身份。索引结果只证明存在相应文献，不证明已经核实材料性质。
4. 优先查看材料生产商的 TDS/SDS、权威技术机构或标准、同行评审论文及可读取的摘要/公开全文。核对产品牌号、材料改性与处理状态、测量条件和适用范围；保留标题、发布方、链接或 DOI。搜索摘要、无法打开的全文和模型常识不写成“已查到并核实”。不要猜造论文标题、网址或来源。
5. 搜索失败、网页拒绝访问或联网能力缺失时，说明具体未取得哪些证据，可继续查其他可访问的公开来源；不修改工具限制或伪装为成功检索。已有本地充分证据可以先回答，未查到的特性明确为未知；环境故障排查不扩展成当前材料任务。

### 给出与测样有关的材料信息

围绕本次目标整理：材料组成与结构、粉体/块体/纤维等形态、孔结构及吸附相关表面特征、吸湿/表面官能团、热稳定性，以及这些特征如何影响气体、分析温度、预处理和 BET/BJH/DFT 方法选择。文献比表面积、孔径或预处理范围应附材料状态和测量条件，不当作当前样品的实测值或直接套用默认设置。

输出包括“本地证据是否命中、补查到的材料特性及来源、对测样方案的影响、仍待确认的关键项”。明确区分直接针对同材料的依据、相近材料参考和基于资料的推断。用户已确定方法时，只补实际缺失的材料依据，不无故改换整套方案。材料尚未明确时可以先给所属类别的有来源说明，但不把类别特性保证为该牌号或当前样品特性。

### 从材料依据到模板

如果用户还要求生成文件，先按人工文档和用户确认条件定下模板，再用 `profiles` 核对目标产品实际已有的完整气体/版本配置，通过 SAM 文件能力生成；已查到的历史和公开资料只补充文档未覆盖的缺口。文档明确的采集参数应显式传入并核对，不让历史默认程序替代它。公开文献不补造气体物性、厂家枚举或 DFT 核文件；配置目录缺少相应能力时指出具体缺口。数值和适用性尚未确认的部分标为草案，文件生成不等于科学适用或可以启动仪器。

外部资料在本次回答中引用，不自动写入用户 LLM Wiki，也不把它们混入固定案例库。没有本地材料案例不自动授权生成文件、摄入资料、登记或启动；按用户本次目标和已有授权继续。

## 推荐与历史参数的边界

- 材料与需求匹配、预处理条件先查“选择规则”；注气、压力段、平衡及报告设置再查“模板定义”。推荐中标明待确认的值仍保持待确认。
- 预处理温度和时间属于样品处理，不等于仪器准备抽真空时间；分析浴温度也不是预处理温度。
- 历史模板保留产品/软件版本、原值、单位、presence、scope、active 状态及字段来源。缺失、null、未启用与有值分别解释；未知单位不猜测。
- 历史 labType=1 是高通量配置证据；当前厂家执行只接受常规模式0，见 Climber 和 SAM 写入契约。
- 历史称量、自由空间/校准体积、端口、UUID 和完成状态不作为本次实验的默认值或执行证明。报告勾选不证明模型文件已安装、报告已生成或科学方法适用。
- 数据库中的摘要和参数证据不是完整 SAM 文件。需要文件时使用当前可用的 SAM 准备能力；只有 profiles 提供的完整配置才能补齐对应产品/版本的物性与结构。

## 从资料走向任务

先明确材料、目标、方法、气体温度、预处理和完整子模板需求，再视需要对比少量历史案例。区分推荐依据、历史设置和用户确认值；没有来源的配置原因保持未知。

准备文件时复用已确认参数和生成结果中的 file.path。需要执行时，另按厂家契约核对当前状态、登记回执和启动回执，不能把检索命中、静态 match 或文件写入成功当作设备已运行。

用户 LLM Wiki 用于已明确导入的纯文本及其知识综合页。任务需要时可作为额外的、带来源的用户资料查阅；不能把其中的概括当成内置规则原文、完整 SAM 或设备当前状态，也不把内置规则和历史数据库送入 LLM Wiki 重写。
