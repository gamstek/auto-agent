# Auto-Agent integration guide

This guide is for applications and AI assistants integrating with an installed Auto-Agent service. Auto-Agent provides persistent chat sessions, trusted skills, and an HTTP API. Use the routes documented here; it is not an OpenAI-compatible or complete OpenCode server. No real device-control API, unrestricted shell endpoint, or business workflow endpoints are provided.

## Start the service
Use the installed executable: auto-agent.exe on Windows or auto-agent on Linux. Bun is not required to run the executable. Configure the model and cloud credentials on the service host, not in client requests.
Set AUTO_AGENT_API_KEY for the cloud model and AUTO_AGENT_TOKEN to a random bearer token of at least 16 characters, then run auto-agent serve (Windows: .\auto-agent.exe serve; Linux: ./auto-agent serve).
The default model is deepseek-flash at https://api.deepseek.com. Without --config, the application creates ~/.auto-agent/config.json on first launch and reuses it without overwriting edits. Use --config PATH to select another JSON configuration; relative dataDir/skillRoots/wikiRoots paths resolve against that file's directory. Set model/baseURL there and keep credentials in environment variables.
For trusted loopback-only use, auto-agent serve --no-token disables client authentication; do not expose this service through a public proxy or port forward. This does not disable cloud provider authentication.
The default address is http://127.0.0.1:4096. If the operator changes host/port, configure your client with the actual service URL. Readiness is indicated by a JSON listening notification on stdout; startup diagnostics and errors use stderr. Check GET /global/health before connecting. Health confirms the service is running, not that model credentials or external devices work.

## Host configuration essentials
Configuration is controlled by the service operator on the host, not through HTTP client requests. See the repository README.md Configuration section for the complete field reference and a strict JSON example; it is not an HTTP configuration endpoint.
- Format: a strict JSON object, not JSONC. Comments and trailing commas are rejected. Omitted fields receive defaults; supplied values must pass validation. Object maps such as interpreters replace the default map rather than merge with it. Unknown fields are ignored, but obsolete wikiDir is rejected; use wikiRoots.
- Selection: explicit --config PATH takes priority and must name an existing readable file. Otherwise, the installed executable creates/loads ~/.auto-agent/config.json and preserves existing edits. Development and build instructions belong in the repository README, not this service integration guide.
- Paths: --config is resolved from the working directory; relative dataDir, skillRoots, and wikiRoots are resolved from the selected file's directory. JSON path values do not expand ~. Escape Windows backslashes, for example "C:\\Users\\user\\agent-data". The generated file uses dataDir="." (data beside config.json); omitting dataDir from a custom file defaults to the user's ~/.auto-agent directory. Simultaneous instances require separate data directories.
- Credentials: AUTO_AGENT_API_KEY is the only source of model credentials; a JSON apiKey is ignored. AUTO_AGENT_TOKEN overrides JSON token, including when the environment value is empty or too short. HTTP requires at least 16 token characters unless serve --no-token is explicitly selected on loopback. JSON noToken cannot disable authentication. Do not put secrets in systemPrompt, scriptEnv, client requests, or source control. Other fields have no general environment-variable override.
- Binding: host=127.0.0.1 and port=4096 by default; port accepts integers 0–65535 (0 selects an available port). Non-loopback HTTP requires allowRemote=true and authentication. allowRemote does not supply TLS or permit --no-token outside loopback.
- Sources: skillRoots=[] and wikiRoots=[] add no external sources. builtinSkills=true and builtinWiki=true still load bundled content; set either false to exclude its bundled sources. Built-in wiki source and analyzed records are bundled together, so bundled-only knowledge is query-ready without an update or model call. External or changed sources still require explicit POST /wiki/update. Only trust known skill roots because their scripts can execute locally.
- Limits: maxSteps=12 (1?100), maxInputTokens=1000000 and maxOutputTokens=16000 describe the model-supported input/output capacities. Optional contextWindow derives maxInputTokens as contextWindow - maxOutputTokens when omitted; explicit capacities must fit within contextWindow. SDK usage.inputTokens/outputTokens/totalTokens are actual reported consumption, not configuration; unknown/invalid usage stops dependent tools. At 90% of estimated input (UTF-8 bytes/3, including tool definitions), old history is summarized via bounded tool-free model calls while preserving critical instructions, current request and evidence. Summary requests are paid and counted in observed run usage. No cumulative token limit or automatic SDK context-window detection. Legacy maxTokens/maxContextTokens settings are rejected.
- Limits: modelTimeoutMs=60000 and scriptTimeoutMs=30000 are milliseconds. outputLimitBytes=65536 caps combined script stdout/stderr; resourceLimitBytes=65536 limits skill resource reads, individual wiki sources, and complete serialized wiki query responses including metadata and warnings; requestLimitBytes=65536 limits HTTP bodies and user-message content in UTF-8 bytes. maxConcurrent=4 limits generations and script execution; titles have a separate budget of that size. All budget/timeout/limit fields require positive integers. Only one generation can run per session regardless of maxConcurrent.
- Scripts: interpreters defaults to {".js":"node",".sh":"bash",".ps1":"powershell.exe"}. Bare node/node.exe prefers installed Node and falls back to embedded Bun only if absent; builtin explicitly selects the embedded runtime. Other executable names/paths remain external. Preserve every needed extension when replacing the map. scriptEnv defaults to {}; credential-like or runtime-control entries and values containing model/bearer credentials are rejected. Scripts do not inherit the full host environment or cloud credentials.
- Prompt and reload: systemPrompt allows up to16000 characters; generated configs store "" to follow the current built-in role. Non-empty text replaces that role, followed by the mandatory runtime contract in one System block. Refreshed host facts and skill catalog form the other System blocks; the adapter merges them as provider instructions. Loaded skill guidance arrives as tool results; references and retrieved records remain evidence. Summary, Wiki extraction and title generation use separate tool-free prompts. Configuration/environment changes require restart; existing explicit settings are preserved. See docs/prompts.md in the repository for the complete prompt map.

## Integration flow
1. Obtain the service URL and bearer token from the operator; never send the cloud API key to the local API.
2. Create a session with POST /session and keep the returned id for subsequent messages.
3. For a final reply, use POST /session/{id}/message. For streaming, subscribe to GET /event first, then submit POST /session/{id}/prompt_async.
4. Filter events by sessionId and correlate each generation using messageId. Query message history after reconnecting.
5. Use POST /session/{id}/abort to request cancellation; do not interpret cancellation as undoing physical effects.

## Discovery and authentication
Default origin: http://127.0.0.1:4096
GET / returns a human-readable integration page.
GET /llm.txt returns this guide as text/plain; GET /llms.txt is an alias.
GET /global/health returns {"healthy":true,"version":"0.1.1"}; version comes from the deployed package metadata.
These documentation and health routes are public and never expose credentials, configuration, sessions, or local skills.
All other routes require Authorization: Bearer <local-token> by default.
The local bearer token is different from AUTO_AGENT_API_KEY (cloud credentials).
Explicit serve --no-token disables authentication only on loopback. Do not assume the service is unauthenticated; do not expose it through public forwarding.
Content-Type: application/json for JSON request bodies. UTF-8 throughout.
No OpenAI /v1/chat/completions endpoint, OpenAPI endpoint, CORS policy for third-party browser clients, or complete OpenCode client compatibility is supplied.

## Sessions
POST /session with {} or {"title":"Optional manual title"} returns HTTP 201:
{"id":"uuid","title":"New session","createdAt":1790000000000,"updatedAt":1790000000000}
Manual titles are at most 200 characters and are preserved. Omitted titles are summarized in the background after a successful reply. Title generation adds a separate model call but does not delay completion or hold a generation slot. At most maxConcurrent titles run, with one pending per session; failed or capacity-skipped titles retry on a later successful message. Shutdown cancels titles. Title events and session.updated may arrive after message.completed.
GET /session returns an array of session objects, newest updated first.
GET /session/{sessionId} returns one session.
GET /session/{sessionId}/message returns the latest page of messages, ordered chronologically.
Both list endpoints accept limit (default 100, range 1–1000) and offset (default 0, nonnegative safe integer). Invalid values return 400. Message offset skips from the newest end; increase offset to retrieve older pages. Equal timestamps use insertion order. Responses remain arrays; an empty page marks the end. Offset pages may shift during concurrent writes. Agent context uses a lazy byte-budgeted history read independent of these pages.
Message shape:
{"id":"uuid","sessionId":"uuid","role":"user|assistant","content":"Markdown text","createdAt":1790000000000}
Session and message objects do not expose internal execution or checkpoint IDs.
Do not infer equipment state or side-effect success from a session's title or agent activity.

## Wiki API
GET /wiki returns state (ready/unbuilt/stale/empty/invalid), source IDs, usable record count, and build time when available. Invalid source/snapshot state is reported in this status object; other API operations return normal error responses.
GET /wiki/query?query=...&limit=5 returns source-cited recommendation records; limit is 1–10. Missing/empty queries or invalid limits return 400. Queries do not trigger model calls or require a chat session. Unbuilt, stale or invalid knowledge cannot be queried. Complete successful query responses fit resourceLimitBytes, including metadata and the evidence warning. Optional availableTerms/hint diagnostics may be shortened/omitted; truncated reports that. If the budget cannot fit mandatory metadata, wiki_output_limit returns HTTP400 instead; normal error responses are outside the wiki-result budget.
POST /wiki/update with no body or {} explicitly runs a paid incremental model build and waits for {sources,rebuilt,builtAt}. All three routes require normal API authentication (or explicit loopback no-token mode). Clients cannot specify arbitrary directories, URLs, models or credentials. Concurrent updates return 409; shutdown rejects new updates with 503 and cancels active updates. Cancellation preserves the previous snapshot and propagates when the runtime signals request abort. No wiki progress SSE, background job or instrument action is implied. Do not blindly retry after a client timeout: check /wiki first. CLI updates cannot share the service data directory; use this API while the server is running.

## Send a message
POST /session/{sessionId}/message
Body: {"content":"Natural-language task"}
Returns HTTP 200 with the persisted final assistant message. This request waits for reply generation only, not background title generation. The server may emit events before the HTTP response arrives.
POST /session/{sessionId}/prompt_async
Same body. Returns HTTP 204 (empty body) after accepting generation, not after completing the task. Follow events and/or message history.
Messages must be nonempty. The default request body limit is 65536 bytes. Only one generation may be active per session; conflicts return 409. Default global concurrency is 4; capacity exhaustion returns 429.
Model failures are recorded as assistant error messages and return errors; do not interpret error text as successful execution.
Do not automatically retry scripts or submissions after an ambiguous disconnect. Read message history and reconcile external effects first.

## Wiki source indexing
Wiki provides compiled recommendations and historical template references. Human knowledge sources are in wiki/sources/, compiled recommendations in wiki/knowledge/recommendations.json, and the readonly template snapshot in wiki/indexes/library.sqlite. builtinWiki=true enables both packaged resources; with no external wikiIndexRoots, template search/read uses the bundled SQLite directly without originals or initial indexing. The database is separately embedded, hash-verified and released under dataDir/builtin-wiki-index. wikiRoots selects MD/TXT for explicit paid compilation (--wiki-update); wikiIndexRoots selects external SAM/SMP directories for explicit local --wiki-index or POST /wiki/index/update with {}. Default external roots are empty and relative paths resolve from config. Startup/chat never scan external templates. Local indexing has no model calls and publishes atomically; use the API while a service owns dataDir.
GET /wiki/index returns template-index state/counts and mode (local-index or readonly-snapshot). GET /wiki/search?query=...&filters=...&limit=3 accepts URL-encoded JSON filters (material directory hint, product status family, gas, analysisType, pressureMode, clientVersion, temperatureMinK/temperatureMaxK, state). All supplied conditions apply; unknown metadata does not satisfy a condition. Results are deduplicated by original content hash and have sourceVerified=false. GET /wiki/source/{id}?query=... returns configuration and JSON-field citations. Local-index reads verify originals; readonly-snapshot reads leave sourceVerified=false and include record.origin with the recorded source hash, relative path and timestamp. No route accepts arbitrary roots, file paths or extractor commands. Responses fit resourceLimitBytes and never silently clip configuration.
The single wiki tool supports action=query (default), action=search and action=read; all require a current successful skill load. Template indexing provides SAM/SMP parameter settings for historical reference. Preserve version, product, units, unknowns and source hashes; confirmed applicability and current device prerequisites are required for execution. Limits:5000 templates,32MiB/template,64MiB extracted snapshot. Read references/wiki.md for the reference workflow.

## Streaming events
Subscribe GET /event BEFORE submitting a message. Include the bearer header (native browser EventSource cannot attach it; use fetch streaming or a client supporting custom headers).
Response: text/event-stream. Heartbeats are comment frames. Each data frame contains JSON:
{"type":"tool.started","sessionId":"uuid","messageId":"assistant-message-uuid","properties":{"name":"skill","toolCallId":"provider-call-id","status":"running","skill":"device-automation"}}
Filter by sessionId and correlate messageId for each generation. Assistant messageId differs from the submitted user message ID. toolCallId correlates a tool's start and end.
Event types and properties:
- session.status: status = busy or idle (agent activity, not device status)
- model.started: step (1-based)
- model.completed: step, usage (SDK inputTokens/outputTokens/totalTokens), totalTokens/inputTokens/outputTokens (compatible flat fields), runTokens (observed cumulative chat and summary consumption), durationMs
- context.prepared: estimatedInputTokens, maxInputTokens (estimate, not SDK-reported consumption)
- context.compressed: removedMessages, estimatedInputTokens, inputTokenLimit, summary usage, durationMs
- model.failed: step, status, message, durationMs
- message.part.delta: delta (raw Markdown fragment), step
- message.reasoning.delta: delta (provider-reported reasoning fragment), step; render separately from answer text
- tool.started: name, toolCallId, status=running; optional skill/path summary
- tool.completed: name, toolCallId, status=completed, durationMs
- tool.failed: name, toolCallId, status, message, durationMs
- session.title.started: empty properties
- session.title.failed: message
- session.updated: session object
- message.completed: message object (final persisted assistant reply)
- session.error: code, message
Steps may contain intermediate assistant text preceding tools. The final history reply contains the final model turn, not every intermediate step. Render Markdown incrementally without treating model text/tool data as trusted HTML.
Reasoning is streamed only when returned by the provider. The official @ai-sdk/openai-compatible adapter maps Chat Completions delta.reasoning_content to standard SDK reasoning-delta parts. It uses independent credential redaction. It is retained as separate SDK reasoning parts in model context/checkpoints, and final-turn reasoning is stored in private SQLite metadata for subsequent requests and session restoration, as required by providers such as DeepSeek when tools are present. Reasoning bytes count towards history/context limits. It is not included in public message content/history or the synchronous final reply. Context compression retains reasoning within retained tool-call/result groups; synthetic historical summaries use untrusted user-data messages rather than assistant turns lacking provider reasoning. Use model.completed/model.failed to close each step's display. The CLI renders it immediately as plain think > text on stderr, filtering terminal controls across chunks without waiting for newlines; --json outputs only public message JSON and suppresses reasoning display. This does not enable a provider-specific thinking mode or manufacture reasoning when the model returns none.
There is no event replay, Last-Event-ID support, or durable event history. A slow subscriber is disconnected when its 64-frame queue fills. Default maximum subscribers: maxConcurrent * 8. Disconnecting SSE does NOT abort generation. Query history after reconnecting; do not resubmit automatically.
Events omit raw script output, full arguments, and skill resource bodies. They expose necessary progress metadata; do not treat them as unrestricted audit logs.

## Abort
POST /session/{sessionId}/abort (no body required)
Returns {"aborted":true} after attempting to stop the active generation and its owned scripts; false if no generation was active or the reply was already completed, even with a pending background title.
Aborting an agent is NOT confirmation that physical equipment stopped or that external effects were undone. Unknown script outcomes require operator reconciliation; such sessions are blocked from further execution. No public resume or reconciliation endpoint exists.

## Errors
Typical JSON response: {"error":"code","message":"sanitized explanation"}. Some auth responses only contain error.
400 invalid input; 401 missing/invalid bearer token; 404 session/route absent; 409 active session, cancellation or ownership conflict; 413 body too large; 429 capacity; 502 model/agent failure; 503 missing cloud model configuration (may be wrapped by agent failure).
Consumers should use HTTP status plus error, not brittle matching of human-readable messages. Unregistered business endpoints /runs, /devices, and /skills are unsupported.

## Client example (JavaScript)
const base = 'http://127.0.0.1:4096';
const headers = { Authorization: `Bearer ${process.env.AUTO_AGENT_TOKEN}`, 'Content-Type': 'application/json' };
const sessionResponse = await fetch(`${base}/session`, { method: 'POST', headers, body: '{}' });
if (!sessionResponse.ok) throw new Error(`Create session failed: ${sessionResponse.status}`);
const session = await sessionResponse.json();
const response = await fetch(`${base}/session/${session.id}/message`, { method: 'POST', headers, body: JSON.stringify({ content: 'Explain available capabilities' }) });
if (!response.ok) throw new Error(`Agent failed: ${response.status}`);
const reply = await response.json();
console.log(reply.content);

## CLI output
Startup diagnostics, warnings, errors, session notices, and progress use stderr. Help and replies use stdout. --json emits newline-delimited JSON for history and replies; stdout contains no startup or progress text. The HTTP service emits its JSON listening notification on stdout. Diagnostics use [info], [warn], and [error] levels; automatic colors are disabled when the relevant stream is redirected or NO_COLOR/TERM=dumb is set.

## Runtime and trust
The operator configures skills, model preferences, and limits on the service host. Clients submit natural-language tasks; model-facing tools are not direct HTTP endpoints. Ask the agent about available capabilities rather than assuming a fixed installed skill catalog. The service has no /skills or /devices endpoint.
The built-in device-automation skill separates preset automation workflows from individual instrument control, enabled by default unless builtinSkills=false. Read references/automation.md for workflow discovery/status, submit-run/run, results and report export through scripts/automation.js. Read references/climber.md for Climber health/status, left-station batch submission and result-archive queries through scripts/climber.js and the Python subservice. These are script operations, not additional model tools. Workflow submission accepts only {deviceId,templateFile}; Climber uses task/experiment fields, sample masses and an absolute existing SAM path. Do not substitute one interface's fields for the other. The workflow backend is simulation-only, with backend=simulation and persistent runs/provenance; Climber requires a configured, reachable real subservice. Local RESUME/CLEAR_ERROR do not physically resume/reset the instrument. Do not retry uncertain writes or infer device completion from command acceptance.
For user-authorized inspection of a single explicit SAM/SMP path, read references/sam.md and use scripts/sam.js inspect/compare with one JSON argument specifying path and product (g5/g12/s60pro). It reads Qt-framed UTF-16BE JSON or UTF-8 JSON, retains provenance and raw field presence, normalizes documented units and compares requested fields without rewriting files or starting instruments. Other-vendor SMP formats are rejected, not guessed from the extension. Files are limited to32MiB; output is bounded and not silently truncated. Host tool argument/time/output limits still apply. Inspection does not scan template directories, certify product-version behavior, convert completed experiments to new templates, or prove execution readiness. Comparison match applies only to requested interpreted fields; report unknown/unsupported fields and warnings.

wiki({skill,query,limit?}) requires a currently loaded skill and returns bounded source-cited recommendations, not an executable configuration. Keyword retrieval searches titles, aliases, fact labels/values and source filenames with NFKC/case/whitespace normalization, bounded Latin/numeric matching and Chinese token expansion. mode=keyword, matchedRecords, truncated and match describe result limits and source previews without changing facts/citations. Queries use at most 256 unique tokens (queryTruncated reports overflow). no_match includes indexedRecords/availableTerms/hint, while matching records too large to return yield output_limit. No embeddings or query-time model calls are used. Built-in wiki is enabled by default; wikiRoots adds external sources relative to the configuration file. --wiki-update explicitly sends changed source text to the configured model; startup/chat never ingest automatically. Updates atomically publish citation-validated records, preserve ranges/issues and reject duplicate identities; failed/cancelled updates retain the previous snapshot.

Model tools are declaration-only. Agent owns scheduling/budgets/events/redaction; script tooling persists audit intent before execution and blocks automatic replay of failed or uncertain writes. Unknown outcomes stop dependent tools and require operator reconciliation. web_fetch({url}) requires no loaded skill: HTTP/HTTPS, 15-second total timeout, 3 redirects, 1 MiB response limit and 20000 output characters. URL credentials are rejected and DNS addresses are pinned. webAllowPrivateAddresses defaults true for trusted deployments and permits loopback/private/reserved destinations for both web tools; set false for public-only access and restart. Protocol/TLS/credential and transport/output limits remain enforced, independently of inbound allowRemote. No cookies/authentication are sent by web_fetch; never include secrets in URLs.

web_search({query,limit?}) requires no loaded skill and uses the OpenCode Exa MCP tools/call protocol at https://mcp.exa.ai/mcp, with optional host EXA_API_KEY authentication (otherwise anonymous access, not guaranteed), JSON/SSE replies, the same address policy, a 15-second deadline, a 256 KiB response cap and no POST redirects. Queries are trimmed to 1..1000 characters; limit is 1..10, default 5. Unverified titles/URLs/snippets are bounded to 16 KiB. Use web_fetch to read selected pages; neither tool opens a browser. Never send private documents, secrets or sample identifiers to external search. Authentication/quota/protocol/transport failures are explicit, not fabricated empty results. Exa HTTP-200 free-MCP quota notices map to WEB_SEARCH_RATE_LIMIT: wait for reset or configure EXA_API_KEY without automatic retries. With webAllowPrivateAddresses=false, Mihomo/Clash Fake-IP DNS addresses 198.18.0.0/15 remain blocked with actionable WEB_FORBIDDEN_ADDRESS guidance; configure real public DNS (e.g. dns.enhanced-mode:redir-host), reload and verify resolution. Default true does not guarantee proxy routing; Auto-Agent does not edit proxy configuration.

Simulation state persists in <user-home>/.auto-agent/simulated-automation. AUTO_AGENT_SIMULATION_DIR in scriptEnv selects an absolute directory outside skill installs and real data; AUTO_AGENT_SIMULATION_DURATION_MS accepts 1..600000 (default 1000). Only the current runs structure is supported. Reads do not write; mutations are locked and atomically published, corrupt/busy state fails closed, and no reset/arbitrary report path/overwrite is supported. Simulated results do not prove physical device state or completed real actions. Generated configuration sets scriptEnv.CLIMBER_SERVICE_URL=http://127.0.0.1:19181 and CLIMBER_TIMEOUT_MS=5000; configure the Python subservice address for the actual deployment and restart. Bare node/node.exe prefers installed Node.js and uses the embedded runtime if the command is unavailable; errors from launched scripts are never retried using another runtime. Operators may explicitly select .js:builtin.
External skills must be explicitly trusted and configured by the operator through skillRoots. Duplicate skill names fail startup. Trusted scripts retain the host's filesystem/network privileges; this is not an OS sandbox and scripts run without per-call approval. Do not accept arbitrary skill directories from client input.
Skill content and necessary tool output may enter cloud model context. Sessions persist in the host's data directory; do not submit secrets that must not be stored or shared with the model provider. Known configured credentials are redacted, but arbitrary secrets cannot be automatically recognized.
Default limits include 12 model steps, maxInputTokens=1000000 estimated input tokens including tool definitions (UTF-8 bytes/3), maxOutputTokens=16000 generated tokens per request, paid model summarization near the input limit (observed cumulative usage only; title calls separate), a 60s timeout per model request, a 30s script timeout, and a 64KiB request body limit. A message may involve multiple steps and scripts, so the total request duration can exceed one model timeout. Background title generation is separately capped at 15 seconds and does not extend the message request. Set client timeouts accordingly or use prompt_async with events/history; a client timeout is not a cancellation request.
One service process exclusively owns a data directory. Interrupted operations are not automatically replayed after restart; ambiguous script effects require operator reconciliation. Clients must not blindly resubmit tasks after disconnects or restarts.
