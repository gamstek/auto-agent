# 应用接入层

corax/lib 实现配置、Corax 宿主约定、Agent 通用 Wiki 装配及 Climber MCP 调用适配。本文未带前缀的 authored 路径相对独立应用包 corax/；仓库脚本通过 auto-agent 的 package exports 导入配置和 Wiki。Agent 循环属于 Corax，知识编译与页面发布属于 packages/llm-wiki；SAM 和设备规则属于 packages/climber-mcp，领域工作流属于 Skill，桌面传输归 Rust，UI 投影归 React。

Corax 将 `lib/` 作为 authored-module 目录编译，其中只放受支持的代码模块；架构说明保存在 docs，不把 README 混入编译目录。

```text
lib/
├─ config/
│  ├─ schema.ts       当前 JSON schema、默认值与 AppConfig 类型，无文件读写
│  ├─ paths.ts        默认配置位置与布局标识，不依赖 schema
│  ├─ index.ts        统一入口：配置 IO、相对路径解析与进程内快照
│  └─ runtime.ts      Corax 数据目录与宿主占用锁
├─ host/              ShellJS 宿主 Provider、进程生命周期和原生路径/文件 I/O
├─ wiki/
│  ├─ index.ts        知识库与预置集合装配，不创建另一个聊天循环
│  ├─ ingest.ts       显式两阶段模型调用，无工具执行或自动重试
│  ├─ desktop.ts      桌面来源状态和单次编译进度，复用同一知识编译引擎
│  └─ reference.ts    通用只读索引适配，元数据过滤、固定引用与分页
└─ climber/
   ├─ index.ts        固定 Node stdio MCP 调用、预算与可信调用身份
   └─ instruments.ts  临时只读投影，不保存厂家任务数据库
```

## 依赖方向

- config/schema 只依赖 Zod 和纯文本来源契约，不依赖模型、桌面或资料连接。
- `config/index` 负责文件读写。需要布局标识的安装脚本只导入 `config/paths`，不会初始化整个 schema。
- `config/runtime` 只管理数据目录占用，`config/index` 提供单份进程内配置快照；二者不依赖桌面 UI、协议或具体业务工具，也不重建 Corax 的运行循环。不另设 lib/runtime 或保留旧路径转发。
- `desktop/src-tauri/src/corax.rs` 直接启停标准 Corax CLI、管理认证和事件传输；`desktop/src/lib/corax-projection.ts` 使用官方 reducer，不读取配置、不创建 Wiki、不生成本地会话 ID。
- `channels/desktop.ts` 在 Corax 进程内使用官方 reducer 和会话句柄提供设置重启、更新等空闲保护所需的活动状态；交互退出不调用活动核验。聊天命令与事件仍使用原生 Corax 路由。
- 知识库 UI 的 `KnowledgeBase` 保留整理受理、轮询及固定引用读取；`KnowledgeWorkspace`、`KnowledgeSources`、`KnowledgeReader` 和 `KnowledgeGraph` 仅负责布局与展示。默认设置侧边栏保持原样，内容区固定为左侧浏览、右侧正文两个主体。左栏通过图谱/目录/资料页签原位切换，没有附加侧栏、遮罩或弹窗；右栏正文独立滚动，来源和固定版本信息折叠展示。窄容器在同一内容区域切换到阅读，并提供返回浏览按钮；恢复宽屏时同一正文无须重新读取即可回到右栏。切换或调整尺寸不取消编译。图谱专注模式只占满知识内容区，不收起外层设置导航。知识页阅读使用独立请求序号，晚到响应不能覆盖新选择。
- 设置中的工具/技能目录由 Rust 读取官方 Corax info 并投影显示字段；`channels/desktop.ts` 仅补充与模型注册共用定义的动态工具元数据，不执行工具或连接仪器。内置能力不可禁用。
- `lib/model.ts` 仅解释模型服务实际返回的认证错误，不按模型名、服务商或 Key 是否为空添加认证要求。
- `sandbox.ts` 仅选择公开 Corax 宿主 Provider，lib/host 负责 ShellJS/文件 I/O；保留原生工具，不在应用里复制 Bash/read_file/write_file/glob/grep 实现。Provider 不需要 JustBash 模板或构建机个人缓存，也不负责设备协议。
- `memory.ts` 仅声明公开 Corax 原生记忆槽：`defineMemory` + `fileMemory` + `sqliteMemory`，路径为 dataDir/corax/memory.sqlite。稳定 namespace=auto-agent、scope=local-user，身份不依赖会话、安装位置或传输令牌；文件随 dataDir 隔离。Corax 拥有召回、并发版本检查及保存/删除工具，应用不复制记忆存储或增设桌面数据库命令。默认召回上限 4000 字符，内容是持久记忆而非可丢弃缓存。
- lib/wiki 为统一 Wiki Tool 装配 knowledge/reference 集合；知识编译与只读检索保留各自数据边界。reference 适配器接收应用绑定的数据源，不在工具 schema 中暴露数据库路径、SQL 或领域专用字段；人工材料规则由 Skill references 阅读。
- lib/climber 只启动随应用发布的固定 MCP CLI；不接受模型指定的解释器、脚本、环境或 shell 命令。SAM schema、完整产品配置、单位和文件写入由 MCP 包拥有。Corax 动态工具直接复用包导出的定义；Skill 只维护操作工作流和解释边界。
- channels/instruments 通过同一 MCP 客户端只读查询，提供给受限 Rust IPC；不调用设备写工具，也不绕过 MCP 直接访问厂家。缓存仅用于显示最后已知状态，失败标 stale，不推断物理状态。
- channels/knowledge 为桌面“知识库”提供固定认证路由。状态检查只读比较原文/规则指纹与完整发布页；整理调用既有 ingest，分页预览复用固定 generation/path/hash 引用。单个进程内操作保存实际阶段、完成数量和取消信号，不创建另一个 Agent 循环、持久任务库或模型工具入口。
- `channels/suggestions.ts` 提供固定认证的欢迎页推荐路由，`lib/suggestions.ts` 以纯文本生成调用当前配置模型，无工具或会话写入。Rust 从原生目录选取最近 3 个会话，仅向后端传递有界显示元数据；Node 通过公开原生流读取各会话最多 80 个后缀事件，提取最近 2 条、每条最多 400 字符的用户提问。不可读历史只使用主题，不初始化、恢复或重放会话。单次生成使用 15 秒预算、最多 768 输出 tokens、无自动重试；推荐最多缓存 8 个上下文结果，成功 5 分钟、失败 1 分钟，不持久化历史或推荐。
- `scripts/` 是入口组合层：选择配置、取得占用锁、启动标准 Corax CLI，并在退出时关闭自己拥有的资源。

## 生命周期

LLM Wiki 写入用独立写入锁和版本发布指针，查询读取既有版本；页面/原文不是缓存。固定内置 SQLite 每次只读访问后关闭，不物化一份用户资料库。Rust 持有令牌、订阅和 Corax 进程树，退出前检查任务。React 只维护投影，重连不重放写入。

MCP 客户端传递 Corax 取消信号，每次调用后关闭自己拥有的 stdio 连接/子进程；不自动重连重放。未发送的写入为 rejected/not-started，发送后回执不明为 unknown。MCP 设备操作和预留存放于 dataDir/climber，重启仍阻断未知写；SAM 未知写入按实际路径/哈希核验。停止 MCP 或取消回复都不证明设备停止。

桌面显式整理绑定保存且已生效的配置 revision 和 Corax 连接 generation。Rust 在派发前预留编译受理 ID；只有同一 ID 的实际终态能解除待确认保护。开始/取消不自动重试，运行或取消中的编译仍阻止设置重启与更新的空闲停止；交互退出始终通过原生确认告知中断后果。离开页面不取消整理，重新进入读取原生编译状态；进程重启后的结果通过持久发布和来源状态核对，不自动恢复模型调用。移除来源配置不删除发布内容。

知识图谱直接读取公开 catalog 的已发布 `related`、来源数量及更新时间，不调用模型、不读取内置案例数据库、不新增图数据库。目录中每页关联元数据上限为 8 KiB，返回完整计数和截断标识，避免长关联列表阻断原有目录分页预算；正文与发布元数据不被改写。节点只来自当前已加载且同一 publication 的非导航知识页，最多展示 48 个；连线只保留两个已展示节点间的明确关联，双向声明合并为一条展示边，缺失或未加载目标不补造节点或连线。力导向布局只在数据或可见尺寸变化时有界计算，隐藏图谱保留上次视图尺寸，不持续运行物理动画。目录分页和节点阅读沿用固定 generation/path/hash，UI 标明已加载范围，不宣称整个知识库的完整关系。

Rust 的后端生命周期锁只用于取得连接句柄和保留在途写请求，不跨普通 HTTP/历史读取等待。只读请求并行执行；写请求独立串行，在途计数和受理记录共同保护退出/重启。会话历史仍来自 Corax 原生流，当前会话按 generation/startIndex 增量同步，不增加推测性活动缓存或本地对话数据库。

`desktop/src-tauri/src/corax/history.rs` 负责当前有限历史接口的 `HistoryQuery`、原生 HTTP 读取、逐行 NDJSON 解码及 `HistoryPage` 返回结构。全量/增量与尾部读取共用解析器，保留原生事件顺序，只暂存未完成的一行，不再把完整 HTTP body 同时保留为大字符串；尾部仍有 2 MiB 总量预算。`corax.rs` 负责选中视图读取租约、代际连接及受理核销，只有完整前缀或有效增量才能核销 pending，部分预览不能。旧的读取函数和游标解析入口已移除，没有旧接口转发或格式兼容层。该重构降低 Rust 侧中间内存开销，不等同于解决 Corax 存储索引扫描成本。

普通消息沿用 Corax 原生受理接口，不在发送前扫描历史或读取流尾游标。当前已确认视图仍由官方投影控制忙闲与输入可用性；Corax 拥有原生消息排队/受理语义。Rust 在调用前保留在途和待确认记录，成功回执的 deliveryId 必须与原生事件 meta.deliveryIds 匹配后才能解除受理保护，不能用旧事件或展示缓存代替确认。事件早于 HTTP 回执时，最多暂存 256 个受理身份用于随后匹配；网络失败、服务端结果不明或缺失身份保留 unknown，不重发，也不凭无关的新事件清除。响应人工输入的游标检查、空闲重启/退出活动核验继续保留。

输入框发送按钮的提交反馈只覆盖发送到受理回执之间的阶段，消息列表不插入“正在提交”或助手内容出现前的通用“正在处理”占位。本次新建并提交的会话在首个原生助手消息出现前静默同步，不短暂展示“正在读取会话”；已有会话加载和真实错误仍可见。这个单会话显示标记在导航、重连和配置边界清除，不参与原生受理、就绪或活动判断。受理后的历史同步继续保护写入，但不延长提交反馈；会话列表刷新独立完成，不占用下一次发送的本地请求锁。

前端职责按数据流划分：`useChat` 仍独占原生事件投影、读取租约与有界历史展示缓存；`useChatController` 负责选中视图、草稿、普通发送/输入响应/取消及本地派发保护，首次提交只是该视图的进入方式。`chat-presentation.ts` 从已确认原生快照统一派生输入、取消、响应和状态提示条件，展示模式不能放宽写入就绪检查。`useBackendLifecycle` 管理启动、健康/协议检查、会话列表恢复和事件订阅，在连接与配置边界统一重置展示身份；这个身份计数只刷新展示与推荐，不替代 Corax 的 generation、游标或受理身份。`useQuestionSuggestions` 自行生成有界使用上下文键。App 保留页面组合、布局和滚动意图，不再内联消息派发和后端启动流程。

欢迎页推荐通过固定 `POST /suggestions` 触发。模型请求保留在途计数以保护设置重启和更新，但不持有聊天派发锁或生命周期锁，不阻塞普通发送。`useQuestionSuggestions` 在 App 生命周期内仅保留最近一组展示结果，连接后预取一次；新建对话首帧复用已有推荐，后续在欢迎页显示或使用情况变化时静默刷新。首次无结果时不先显示通用问题，固定标题与列表占位避免回退闪动；明确失败后才使用通用问题。离开页面允许同身份预取完成，更新请求序号及连接/配置身份防止迟到结果覆盖；身份变化立即隐藏旧推荐，不持久化。失败时保留可用问题，不显示生成或错误状态文字。匿名模型服务可直接生成，不以 API Key 是否存在判断模型可用性。

`desktop/src/lib/chat-history-cache.ts` 实现有界、进程内的跨会话历史展示缓存，保留官方 Corax 投影及其 generation/游标，不持久化。非当前会话最多保留 16 项，按 UTF-16 字符串、对象和属性开销保守估算的内存预算为 64 MiB，按 LRU 淘汰；超预算的单个会话仍可正常打开，但离开后不缓存。当前会话独立持有投影，不计入非当前缓存预算。切回命中项时在首帧展示，再按 generation/startIndex 读取未读后缀并建立新的读取租约/订阅。展示内容与本次视图已确认的忙闲、就绪和写入受理状态分离：同步成功前不启用发送、取消或输入响应，也不从缓存推测当前活动。代际改变时清空缓存，游标不兼容时丢弃该前缀并从零重读。启动、重新连接及设置保存边界保守清空展示缓存，以覆盖配置/数据身份改变和延后应用设置；普通断连期间仍可查看当前历史。淘汰只释放展示引用，不取消 Corax 任务，也不重放写入。

聊天视图的临时读取租约由 Rust 持有，WebView 仅提交有序的 open/close 短命令。视图切换会取消其在途历史 HTTP 请求、释放旧事件订阅；请求等待保持在生命周期锁外。旧视图标识无法订阅或关闭新视图。该读取租约与任务生命周期、待确认写入及在途写请求计数相互独立。

`desktop/src-tauri/src/shutdown.rs` 统一主窗口/悬浮窗关闭、Alt+F4、菜单和 IPC 退出。每次交互退出先保留退出意图，立即显示 Rust 原生“关闭应用 / 继续运行”确认，提示本地任务中断、已下发仪器任务可能继续运行及未知写入需核验。弹窗前不获取后端生命周期锁、不查询活动或扫描历史；确认期间新写入被退出意图拦截，只读同步可继续。只有明确选择“关闭应用”才调用 Rust 内部进程树停止，继续运行或关闭对话框均不停止任务；退出异常释放意图，不伪造已发生操作的回滚。重复退出请求不重复弹窗，也不抢占更新的退出状态。Rust 保存自有进程树的弱引用句柄，使确认后的关闭不被繁忙生命周期锁卡住，不按名称全局查杀进程。force-stop 不注册为 IPC，不发送设备停止/回滚命令，也不核销未知写入。设置和更新继续使用严格的空闲停止路径。

普通消息发送遵循官方 SDK 的会话就绪协议：仅对 HTTP409 且 code=session_not_ready 的明确未受理响应有界等待；网络错误、响应解析失败和服务端效果未知不重发。明确拒绝与未知受理使用不同错误元数据，界面保留未发送草稿。

更新下载与 Corax 活动核验分离：点击安装先下载并通过 updater 签名校验，不在下载前扫描会话或持有生命周期锁。下载完成后保留退出意图以阻止新写入，再在生命周期锁内执行一次原有空闲保护停止；核验失败或工作未结束都不启动安装器。UI 使用下载进度及 checking/installing 阶段事件区分失败位置，只读状态请求的连接失败或超时不使用“不要重复提交”的未知写入文案。安装器启动失败仍释放退出意图并按既有逻辑恢复已停止的后端，不提供 force 更新入口。

移动后的模块不保留旧路径转发文件。修改结构时同步更新 authored modules、CLI/桌面入口、原生配置测试和发布资源验证。

聊天页的 `InstrumentMonitor` 与仪器页复用 `useInstruments` 的原生只读快照、刷新及退避轮询。`useInstrumentMonitor` 只管理容器断点、临时展开偏好与短暂动画存在状态，按钮选中态对应展开意图；浮窗展开且后端已连接时才订阅和轮询，收起即停止读取并设置 inert/aria-hidden，退出动画结束或有界兜底计时后释放展示，快速重新展开可中断退出。后端/配置展示身份变化会重新创建浮窗读取状态，迟到结果不能恢复旧展示；失败或未确认的状态不推断为在线、空闲或无任务。宽窄屏均使用覆盖在聊天内容区的浮窗，开合不改变正文和输入区的位置、宽度或消息滚动偏移，不划出独立滚动列；工具栏有独立层级且不参与消息滚动。自动跟随与“回到最新”只调整消息容器的 scrollTop，不通过 scrollIntoView 滚动外层窗口或把工具栏滚出视口。

历史显示由 `useMessageWindow` 管理，首屏最近 20 条，向上滚动接近边界时每次增加前 20 条，按钮作为键盘和手动后备入口。已渲染消息的身份作为滚动锚点，补充旧内容不改变原消息屏幕位置，阅读旧消息时也保留该起点；会话或后端展示身份改变会重置渲染窗口。`CoraxProjection.catchUp` 仍使用官方 reducer 处理有序原生前缀，每批最多 128 个事件或约 8 ms 后让出主线程，并在恢复时检查读取视图是否仍有效；首次重建完成前不确认当前视图。原生流与增量游标不变，不用尾部截断代替完整任务/输入状态，也不声称 Corax 0.1.0 已支持独立的历史消息分页快照。

冷打开已有会话时，`useChat` 在同一前台读取租约内先完成有界尾部读取，再启动完整原生同步，不并行争抢冷读。Rust 的专用 `events?tail=N` 只转发固定原生 stream 路由的负游标、`follow=false` 和尾索引头，限制事件数 1..2048、响应 2 MiB。前端默认窗口 512；优先用官方 reducer 展示从真实 turn.started 开始且属于已载入轮次的事件，忽略窗口外旧轮次的迟到事件。单轮超过窗口时，从真实完成事件投影末条终稿，保留原生消息身份并明确标为最近回复预览，不重建或假造缺失的过程；没有可用终稿或起点时才扩大为 2048。

部分预览不核销受理，也不能令 ready=true；预览与完整投影分别保存，完整前缀及当前订阅确认后才可写。若 Rust 验证 startIndex=0、事件数覆盖 revision，且首事件为 session.started（或空前缀），则这是完整原生前缀而非片段，可以执行原有精确受理核销并直接交给完整投影，避免重复冷读。切换、失效代际和迟到响应均不能将部分预览升级为可写状态。缓存命中或首次新建提交跳过预览。投影通过 scheduler.yield/MessageChannel 让出任务，不用递归 setTimeout 链；仍保持每批至多 128 事件/约 8 ms 的预算和取消检查。这里优化的是尾部先显示，大型会话的全量状态确认仍在后台进行。

隔离假模型的事件密度不能代表实际历史：真实诊断中，13 轮会话有 26,243 个事件，末尾 2,048 个仍没有 turn.started；旧的 128/512/2048 顺序寻找起点会使预览失效并退回全量读取。去掉诊断 IPC 拦截、清空进程内展示缓存后，修正前端的四个会话首屏分别约 0.53/3.67/0.38/0.78 s；最重会话的完整状态同步仍约 13.9 s。单独尾部读取也存在数秒延迟，因此不能把 UI 优化宣传成已经消除 Corax 存储读取成本。这些只记录匿名标签、耗时与规模的结果不是性能保证，不保存会话正文、标题、身份或凭据。

## 构建、安装与验证脚本

- `desktop/scripts/prepare-runtime.ts`：构建与部署 `desktop/src-tauri/runtime` 资源，不执行用户目录清理。
- `desktop/scripts/release.ts`：校验发布版本和签名环境、构建签名安装包并生成 feed manifest；路径从脚本位置确定。
- `scripts/shared/`：入口共用的 Node 子进程和 pnpm 调用辅助，不属于 Corax authored-module 运行层。
- `desktop/src-tauri/installer/`：NSIS hook 和专用 reset-data 实现；只有安装器执行重置。
- `desktop/tests/native/smoke.ts`：原生窗口、配置与会话联调，不混入构建脚本。
