# 提示词职责

应用 authored 路径（instructions、tools、skills）相对仓库的 `corax/` 目录。

| 所有者                                | 内容                                              |
| ------------------------------------- | ------------------------------------------------- |
| instructions.ts                       | 身份、通用工作原则与真实宿主环境                  |
| memory.ts                             | 原生记忆装配、业务记忆范围与内容边界              |
| lib/suggestions.ts                    | 欢迎页问题推荐、使用上下文与纯 JSON 输出约束      |
| tools/wiki.ts                         | 通用 Wiki 集合、查询、显式摄入及来源/分页契约     |
| packages/climber-mcp/src/contracts.ts | SAM 与四项设备工具的 schema、操作边界及未知写恢复 |
| tools/climber.ts                      | 按配置向 Corax 暴露 MCP 契约，不复制领域指导      |
| device-automation Skill               | 方法、材料规则、文件准备与设备/流程任务路由       |
| knowledge-base Skill                  | 用户资料查询、原文核对与显式整理的工作流          |
| packages/llm-wiki/src/prompts.ts      | 摄入专用分析/生成提示词，不复用聊天角色           |

`instructions.ts` 使用 `<role>`、`<working_principles>` 和 `<environment>` 区分角色、通用原则和运行环境。自定义 systemPrompt 只替换 `<role>` 内的内容，共享原则和真实环境仍追加一次。工作原则按目标与约束、证据与判断、执行与核验、沟通与交付组织，不重复具体工具或领域流程。

环境块在每次 `turn.started` 时采样宿主时间，提供带星期及偏移的本地时间、IANA 时区和 UTC 时间；它是本轮时间基准，不是持续更新的时钟。模型标识取自与 `agent.ts` 相同的进程内配置，只说明当前配置，不推断模型厂商、训练截止时间或实际服务能力。其余信息为宿主平台/架构、实际 Node.js 版本、真实 Bash、工作及技能目录和路径约定；不注入密钥、传输令牌或服务地址。原生文件工具/Bash 的 POSIX 表示不改变其他工具各自的路径契约。

Corax 自身注入可用技能目录、匹配后加载及资源相对路径指导，并提供默认工具契约。技能调用是框架向模型提供的能力和指导，不是模型脱离框架自带的功能；应用无需再在角色或工作原则中重复“按需加载技能”。角色不重复工具 schema、仪器常量或数值程序。

## 长期记忆

`memory.ts` 负责 Corax 原生记忆的存储和作用域装配，其 `description` 使用 `<memory_policy>` 集中描述业务记忆范围。Corax 会把该描述附加到记忆工具描述中；原生 `fileMemory` 已提供保存/删除契约，并在召回时说明记忆是可能过时的数据而非指令。框架不要求在 `instructions.ts` 再写记忆专用提示词。

应用侧明确主动保存的时机与范围：用户直接陈述的稳定仪器背景、长期材料与测试需求、命名及报告习惯，应调用原生记忆工具保存，不等待用户说“记住”，也不逐条请求记忆授权；遵守用户不记录或忘记的要求。可复用实验条件仍须经用户确认并保留适用范围，不将单次参数、模型建议或推测升级为默认条件。持续讨论或明确跨会话推进的项目，只保留跨会话仍有用的简短目标、已确认约束和持久资料引用，不要求用户说“下次继续”，也不记录当前进度、待办或其他执行细节。完整 SAM、详细方案与结果保留在实际文件中，明确授权后才整理进知识库。

保存前对照已召回内容去重；用户更正稳定事实时，通过原生记忆工具移除过时条目并保存更正。仅在工具确认成功后简短告知已保存或更新。记忆仍由模型调用工具时落盘，没有新增后台自动提炼或额外模型调用链。

凭据、配置副本、临时参数、执行状态和回执不进入记忆；当前设备、批次和未知写入状态须另行核验。记忆与其他资料同样受通用证据及授权原则约束，不在全局原则中重复整套记忆规则。删除记忆与删除历史聊天是独立操作，不把聊天历史展示缓存或 LLM Wiki 当作长期偏好存储。

## 内置资料

两份材料规则是 Skill references/materials 内的人工指导，按需通过原生资源阅读。历史 SQLite 是 Wiki reference 集合的只读证据，用户知识在 knowledge 集合；二者共享通用 Wiki Tool，不共享摄入流程。Skill 按目标组织方法解释、资料查询、文件准备和执行，不再提供领域专用查询工具或 guidance 操作。加载技能不自动提供设备连接或宿主执行。

新方案的模板选择以《选择规则》和《模板定义》为主：前者决定材料/需求匹配及模板名称，后者定义采集和报告设置。用户已确认条件保留；历史 SAM 和网络资料只补文档未覆盖的具体缺口，不覆盖已有推荐。`profiles` 是产品/版本文件底座，显式文档参数应通过文件工具写入并检查；底座来源案例或 `programOrigin` 不代表本次推荐依据。用户指定文件的局部修改则保留未要求改动的字段。

文件任务在返回实际文件结果及相关核验范围后结束，不因生成 SAM 自动进入设备控制。概要报告内部选项未由当前 inspect/compare 返回，不能以整体报告勾选代替子项核验；支持路径和缺口由 Skill 的 SAM 写入参考表说明。外部流程模拟器仅用于用户明确要求的模拟，不是真实服务缺失时的替代。开发用行为/触发评测规格位于 `tests/skills/device-automation/`，不作为发布资源或实际模型评测成绩。

当前应用通过 Climber MCP 的 sam_file 提供 SAM 宿主文件能力；启用配置后再提供设备工具。MCP 包拥有工具契约、实现与完整产品配置，Skill 参考文档拥有产品、单位和工作流指导；角色不重复这些契约。通用宿主执行由独立的 ShellJS Provider 提供，仍保留 Corax 原生工具；角色只追加实际 OS、工作目录和资源目录等运行环境事实，不复制工具 schema 或领域程序。

材料咨询中的“本地资料不足 → 公开材料检索 → 来源核验 → 方法/模板建议”由 device-automation Skill 及其 Wiki 参考文档组织，复用当前实际可用的 Corax 搜索与网页读取能力。网页读取不等于提供了独立搜索工具；公开搜索页或文献索引可用于发现来源，材料特性仍需核验正文、摘要或技术文档。网络限制必须如实反馈，外部查证不自动摄入 Wiki，也不自动授权生成文件或控制设备。

## 欢迎页推荐问题

`lib/suggestions.ts` 拥有推荐专用提示词，不复用聊天角色或摄入提示词。输入是最近 3 个会话的有界主题与提问，以及当前可用能力；历史内容按非可信数据处理，不能覆盖输出约束或授权操作。不从历史推断默认测试参数、当前设备状态或项目仍在执行，也不推荐直接登记、启动、重放未知写入或删除数据。模型只返回四个简短问题的 JSON，无工具、无 Agent 循环，失败不自动重试。

连接后预取一组推荐，欢迎页显示时再按使用上下文静默刷新，不显示生成中或失败文字，不影响输入。展示结果保留于 App 生命周期，新建对话首帧直接复用；首次尚无结果时不插入通用问题，明确失败后才回退，后续失败保留已有可用问题。标题固定为“为你推荐”，连接或配置身份变化时丢弃旧展示结果。推荐结果与聊天记录、记忆及知识发布彼此独立，不将推荐问题当作用户确认；点击问题仍走原生聊天受理和对应 Skill 的操作核验。

## LLM Wiki 摄入

产品页面统一称“知识库”，`knowledge-base` Skill 只组织任务流程；`wiki` Tool 拥有操作契约，`packages/llm-wiki` 拥有知识编译实现。Skill 不重复参数、分页和模型生成格式。桌面“添加资料”只登记来源，“开始整理”才授权调用模型；查看状态和移除来源均不隐式摄入。

分析阶段结合纯文本、purpose/schema、目录和相关页，输出简洁的最终事实分析、实体、概念、关联与冲突；生成阶段据此写出/合并 Markdown 页。都不要求输出隐藏思维过程。

原文和现有页是证据，不覆盖维护指令。内部模型调用没有工具或文件执行权限；应用验证路径、来源引用和发布基线后才写入。更新不能丢弃其他来源的引用，矛盾和未决项继续保留。

普通查询只读已整理页面，必要时回读固定原文。只有用户明确要求导入/更新才 ingest；不把聊天回答自动晋升为事实。按 completed 说明批次完成、取消与失败，不声称全部回滚或自动重试。

结构 lint 不代替语义判断，文档结论不证明设备状态或科学批准。
