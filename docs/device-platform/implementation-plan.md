## 1. 依赖顺序

```text
P0 契约与边界
  ↓
P1 通用 MCP 客户端 + 操作策略/审计
  ↓
P2 Climber MCP + 统一设备入口
  ├── P3 仪器只读页面
  └── P4 Skill 改造与旧真实写入口收口
          ↓（P2/P3/P4 均验收）
P5 单设备持久化流程
  ↓
P6 重启恢复/核对/取消闭环
  ↓
P7 常驻服务模式
  ↓
P8 定时计划
  ↓
P9 跨设备流程
```

P3 的 UI 可以先用契约 mock 开发，但接入真实状态必须依赖 P2。开发中可以并行推进互不依赖的工作；正式设备控制入口切换以集成验收为准。

定时基础表可在 P5 预留，但“关掉桌面继续按时运行”的产品能力必须等 P7 完成。P9 需要第二种真实设备的契约和验证环境，不能仅用模拟设备通过测试后宣称已接入。

## 8. P6：故障恢复与核对闭环

这里是工作流级恢复。已有的通用工具 unknown 审计及 Climber 服务端预留是基础能力，不能据此勾选本阶段的续行、等待和取消任务。

任务：

- [ ] 启动恢复先扫描活动流程、未决操作和设备预留，再允许新写入。
- [ ] prepared 与 dispatching 区分恢复，后者中断一律先 unknown。
- [ ] waiting_device 从持久化 nextWakeAt 恢复，有 deadline 和身份检查。
- [ ] 追加核对记录，保留原 unknown 审计；显式 continuation 跳过已核实发生的动作。
- [ ] logicalActionKey 防止 continuation/新操作编号绕过未决写入。
- [ ] cancel_requested 与实际设备停止分离，界面说明当前取消的范围。
- [ ] 数据库不可写时停止进一步设备写入；关键结果落盘失败不能继续依赖动作。
- [ ] 设备预留失联先 recovering，不能按心跳超时直接当空闲。

必须故障注入的窗口：

| 注入点                              | 期望                                     |
| ----------------------------------- | ---------------------------------------- |
| prepared 提交后退出                 | 重启重新校验后可调度，未出现额外厂家调用 |
| dispatching 提交后、发送前退出      | 保守 unknown，不自动发起 register/start  |
| 厂家接受 register，客户端未拿到回执 | 不启动、不重复登记，保留 batchId         |
| 厂家接受 start，响应丢失            | 不重新登记/启动，进入核对                |
| 回执正确但结果事务失败              | 阻断下一步，恢复按未决效果处理           |
| waiting_device 时重启               | 继续查询原批次，无第二次 start           |
| 当前 task 被另一批次替换            | 进入核对，不把其他批次完成当作本批完成   |
| UI/SSE 断线                         | 重连只读快照，不重放写请求               |
| 取消请求遇到在途写入                | 不宣称仪器停止，不擅自释放占用           |

验收要求：测试以真实持久化数据库和进程退出窗口为基础，核对厂家 mock 的请求次数和批次身份，不能只测试内存状态机。

- `tests/unit/mcp-*.test.ts`：目录/策略/schema/错误分类。
- `tests/integration/mcp.test.ts`：本地 MCP 子进程、协议、退出和重连。
- `packages/climber-mcp/tests/`：厂家 HTTP mock 与 MCP 契约。
- `tests/integration/devices.test.ts`：快照、缓存、固定 API、写入仲裁。
- `tests/integration/workflows.test.ts`：实例执行、等待、预留和状态持久化。
- `tests/integration/workflow-recovery.test.ts`：进程中断及不确定写入。
- `tests/unit/workflow-schedules.test.ts`：可控时钟、时区与触发策略。
- `desktop/e2e/`：仪器页、流程展示、断线/过期和无模型请求。

包级测试由 pnpm workspace 的根 `test` 命令递归执行；根 `bunfig.toml` 只扫描根 tests，各包维护自己的测试目录，Playwright 单独执行。内部包使用 workspace:* 和 exports，不跨包导入 src 文件。

### 每阶段完成清单

- [ ] 实现与该阶段公开契约一致，不把下一阶段接口提前宣称可用。
- [ ] 失败和未知结果有测试，未破坏现有脚本审计/对账和独占数据目录行为。
- [ ] mock 测试无真实模型费用、无真实仪器写入、无用户目录污染。
- [ ] 新配置已在 schema、示例、桌面保存保留规则和 README 中同步。
- [ ] 新 HTTP 路由已在 `llm.txt`、鉴权测试和 Rust 白名单中同步。
- [ ] Skill/工具 prompt 只更新自己负责的内容。
- [ ] 日志和诊断 ZIP 未扩大到原始操作参数、样品正文或凭据。
- [ ] 发行版包含运行必需的 MCP 产物，明确模拟、mock 与真机验收的区别。
- [ ] 阶段结果回写本计划，记录已完成内容、未决问题与实际测试命令。
