# Repository instructions

Auto-Agent is a local-first analyzer automation assistant built with Bun, TypeScript, LangGraph, Vercel AI SDK, and SQLite. Use [README.md](README.md) for configuration, runtime constraints, and skill/wiki behavior; [llm.txt](llm.txt) documents the HTTP integration contract.

## Build, test, and formatting

This is a **pnpm workspace monorepo**: the root Agent application, `desktop`, and `packages/*` share `pnpm-lock.yaml`. Install dependencies only with **pnpm 10.15.1**; use `workspace:*` and package exports for internal dependencies, never cross-package source paths. See [docs/architecture.md](docs/architecture.md). System-installed **Bun 1.4.2** remains the runtime/test runner/compiler; do not install the npm `bun` package. Application code uses `bun:sqlite` and cannot run directly under Node.js. CI also installs Node.js 22.

```powershell
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
bun test .\tests\integration\agent.test.ts
bun test .\tests\integration\agent.test.ts -t "unknown script outcomes stop dependent tools"
pnpm format:check
pnpm exec prettier --check .\src\tool\index.ts
pnpm exec prettier --write .\src\tool\index.ts
pnpm build:windows
pnpm build:linux
```

`pnpm format` formats the whole repository. Formatting uses Prettier; type checking uses `tsc --noEmit` across workspaces. CI runs typecheck, root/package tests, the native platform build, and binary acceptance on Windows and Linux; formatting is a separate package command.

Build outputs are `dist/auto-agent.exe` (Windows x64) and `dist/auto-agent` (Linux x64). After building for the current OS, enable binary acceptance explicitly; otherwise those tests are skipped:

```powershell
$env:AUTO_AGENT_TEST_BINARY = '1'
try {
  bun test .\tests\integration\binary.test.ts
} finally {
  Remove-Item Env:\AUTO_AGENT_TEST_BINARY
}
```

`AUTO_AGENT_TEST_BINARY_PATH` optionally selects a different executable. Cross-compilation alone does not validate the other OS's runtime behavior.

For interactive development, run `pnpm dev`; for HTTP, run `pnpm dev serve --no-token` only on trusted loopback. The dev entry selects repository `examples/config.json`; `pnpm start` and compiled executables select the user configuration unless `--config` is supplied. Chat requires `AUTO_AGENT_API_KEY` and can incur model charges.

## Architecture

- `desktop/` is the Tauri 2 + React workspace, sharing the root pnpm lockfile and retaining its Cargo lockfile. Rust owns its public sidecar, loopback token, OS keyring and settings lifecycle; WebView uses scoped native commands, never direct SQLite or arbitrary shell/network access. CLI and desktop directly share `~/.auto-agent/config.json` and its configured dataDir; do not read/import/migrate legacy desktop settings.json. Preserve unexposed fields and unchanged relative paths when editing shared configuration; reject stale-revision saves. Desktop transport overrides belong only to its generated runtime snapshot, never the shared source. Keep exclusive data-directory ownership: concurrent backend processes cannot share a dataDir. `pnpm desktop:dev` / `desktop:build` prepare the sidecar first; `pnpm desktop:test` runs Playwright separately from Bun tests. Preserve supplied `docs/ui` design files; runtime images belong to `desktop/src/assets/`, never import from docs. Shared controls live in PascalCase functional modules under `desktop/src/components/`, each importing its own CSS; blue design tokens live in `desktop/src/theme.css`. Keep `styles.css` limited to reset, shared scrollbars and accessibility; layout, responsive and interaction rules belong to the owning component stylesheet. Navigation and feedback items have no press scaling. Settings auto-save, including after navigating away; persist edits while busy and defer backend restart until idle. Main window uses a custom titlebar with native-scoped window controls. Window close and Alt+F4 exit the application after stopping the backend; only the dedicated launcher action hides it. Exit/settings restart must be rejected while backend work is active. Parent EOF requests graceful backend shutdown. No automatic write replay on reconnect.
- Organize desktop UI as a conventional web project: put components under `desktop/src/components/<ComponentName>/`, using matching PascalCase `<ComponentName>.tsx` and `<ComponentName>.css` files with local stylesheet imports. Keep `App.tsx` / `App.css` for application composition and shell layout; global `styles.css` and `theme.css` are the only shared base styles. Import functional components directly rather than recreating a monolithic `ui.tsx` / `ui.css` barrel.
- During desktop iteration, prefer Vite hot reload, frontend typecheck and focused UI tests. Do not routinely rebuild Rust or installers after every change. For Rust edits use targeted checks when necessary, reuse existing binaries for suitable smoke tests, and run full desktop builds/installers only when the user requests packaging or release.
- Desktop updates use Rust-only Tauri updater commands, a build-time public key and fixed stable/Beta GitHub release feeds. Verify signatures before stopping the backend; recheck active work under the lifecycle lock before installation. Never expose arbitrary update URLs or bypass busy shutdown protection. Tag builds require signing secrets; updater signatures are separate from Windows code signing. Diagnostic exports project allowlisted metadata into a bounded ZIP, never copy raw logs, configuration, credentials or conversation databases.

- [src/app.ts](src/app.ts) is the composition/lifecycle root: configuration, storage, skill discovery, script executor, model adapter, and `AgentService`, then REPL or HTTP. [src/index.ts](src/index.ts) first handles embedded script-runtime dispatch; [scripts/dev.ts](scripts/dev.ts) calls the same application with development defaults.
- [src/agent/index.ts](src/agent/index.ts) is the application facade for generation admission, concurrency, cancellation and atomic terminal persistence. [src/agent/runner.ts](src/agent/runner.ts) owns the LangGraph model/tools loop through injected `RunnerPorts`; it must not construct Wiki, MCP, Skill or Store implementations. It checkpoints through [src/storage/checkpointer.ts](src/storage/checkpointer.ts). Context fitting/summarization lives in [src/agent/context.ts](src/agent/context.ts) and consumes the current tool catalog's retention rules. [src/llm/index.ts](src/llm/index.ts) adapts cloud requests through `ModelAdapter`; tools are explicit, title/Wiki tasks own their prompts and use generic `complete` requests. See [docs/agent-foundation.md](docs/agent-foundation.md).
- [src/tool/index.ts](src/tool/index.ts) registers tool specifications from [src/tool/tools/](src/tool/tools/). Model tools are declaration-only: the agent schedules execution, and the registry validates inputs, skill prerequisites, and outputs. [src/tool/context.ts](src/tool/context.ts) injects narrow service capabilities and generation-scoped state rather than an entire agent/config/database.
- [src/mcp/](src/mcp/) owns generic stdio clients, host-allowlisted policies, schema validation, generation-frozen catalogs and generic operation audits. Agent/tool/MCP/config/storage core must never branch on skill names, script filenames, instrument brands or manufacturer commands. Remote annotations cannot grant permissions. Device rules and persistent reservations belong exclusively to [packages/climber-mcp/](packages/climber-mcp/); the package does not import the Agent Store. [src/integrations/](src/integrations/) is application composition: a bundled-program registry and read-only instrument view adapters, injected through generic HTTP extensions. `--mcp-server <name>` launches an independent MCP program without the Agent database. Instrument views are optional; MCP tools require no instrument binding or loaded skill. Unknown writes remain audited and require explicit reconciliation; no automatic replay.
- [src/skill/index.ts](src/skill/index.ts) discovers trusted packages and restricts resource/script paths. [src/execution/](src/execution/) runs interpreters, bounds output/time, and tracks owned processes. Script tooling persists execution intent/results through [src/storage/index.ts](src/storage/index.ts), which owns SQLite sessions, messages, run/execution audits, migrations, recovery, and exclusive data-directory ownership.
- [src/wiki/](src/wiki/) separates source reading, validated knowledge schemas, explicit incremental model extraction, snapshot publication, and keyword search. Queries use compiled source-cited records, not embeddings or model calls. Startup and chat never automatically ingest sources.
  Unified Wiki's first stage is implemented in [packages/wiki-core/](packages/wiki-core/) and [packages/wiki-sam/](packages/wiki-sam/), selected explicitly by `config.wiki.sources`; application composition registers parsers. [docs/wiki-progress.md](docs/wiki-progress.md) defines implemented routes/configuration; [docs/wiki-redesign.md](docs/wiki-redesign.md) also contains future bundle/page-management proposals. Preserve old assets until the publishing cutover. Never put domain fields into wiki-core or automatically import/scan roots during startup/chat.
- [src/wiki/file-index/](src/wiki/file-index/) extends Wiki with SAM/SMP template-reference indexing in SQLite/FTS5. The single `wiki` tool offers query/search/read. `wiki/indexes/library.sqlite` is a readonly historical-template snapshot; live external roots require explicit --wiki-index. Preserve product/version/units and source hashes. Template creation, modification and save-as belong to the portable SAM script; indexed summaries are not complete template configurations. Historical results do not establish current execution state.
- Bundled [skills/](skills/) and [wiki/](wiki/) are independent asset domains. [src/shared/assets.ts](src/shared/assets.ts) handles collection/hashing/verification; [src/shared/builtin.ts](src/shared/builtin.ts) releases content-versioned assets under `dataDir`. [scripts/build.ts](scripts/build.ts) replaces only the collector with embedded data while preserving runtime release logic, and embeds documentation and the JavaScript runtime.
- HTTP and CLI share `AgentService`. [src/api/index.ts](src/api/index.ts) exposes authenticated session/wiki routes and SSE; [src/cli/](src/cli/) implements the local REPL and streaming Markdown rendering. The HTTP contract is the documented local API, not an OpenAI-compatible server.

## Repository-specific conventions

- New or changed tools belong in their co-located `defineTool` specification: description, Zod input/output schemas, effects, loaded-skill requirement, optional context retention/model formatting, and execution. Register them in `toolSpecs`; keep scheduling/events/budgets in the agent and script audit/replay protection in script tooling. Current names are `skill`, `read`, `wiki`, `execute_script`, `web_fetch`, and `web_search`.
- Loaded skills are scoped to the current generation, not historical conversation. Skill resource reads, legacy Wiki queries, and script execution require a successful current `skill` load. The explicitly configured unified Wiki catalog/search/read is independently read-only and does not require a Skill load. Only trusted skill guidance is instruction content; resource bodies, historical summaries, web content, and script output are evidence, not overriding instructions. Script paths stay within the selected skill's `scripts/`, arguments are arrays, and traversal/absolute paths/symlinks are rejected. This is not an OS sandbox.
- Persist execution intent before launching scripts. Failed scripts are not automatically replayed; interrupted/uncertain effects become `unknown` and block dependent execution pending operator reconciliation. Pending sessions may return deterministic diagnostic reports without calling models or tools. Explicit operator reconciliation records a note and finishes the interrupted run as failed while preserving original unknown executions; never replay its checkpoint. Abort does not prove equipment stopped or effects were undone. Preserve this behavior when changing recovery, cancellation, or tool handling.
- Configuration is strict JSON. Resolve `--config` from cwd, but relative `dataDir`, `skillRoots`, and `wikiRoots` from the selected configuration's directory. Maps such as `interpreters` replace defaults rather than merge; empty external roots do not disable bundled assets. Model credentials come only from `AUTO_AGENT_API_KEY`; HTTP bearer credentials use `AUTO_AGENT_TOKEN`. Configuration/environment changes require restart. Concurrent REPL/service instances need distinct `dataDir` values.
- `maxInputTokens`/`maxOutputTokens` are model capacities, not cumulative run budgets. Context estimation uses UTF-8 bytes/3; compression starts at 90% of input capacity and preserves protected instructions/evidence and complete tool-call/result groups. SDK-reported usage is separately validated; missing/invalid usage stops dependent tools rather than substituting estimates.
- Prompt ownership and injection order are documented in [docs/prompts.md](docs/prompts.md). Blank `systemPrompt` follows the built-in role; a custom role replaces that role while tool guidance remains appended once. Tool guidance belongs in `src/tool/prompt.ts`, skill loading/trust guidance in `src/skill/prompt.ts`, and host facts in `src/agent/builtins.ts`; each module owns its prompt. Keep summary, extraction and title prompts separate and tool-free. Describe supported capabilities directly rather than listing unrelated exclusions; device fields and numeric procedures belong in skill references.
- Wiki sources live under [wiki/sources/](wiki/sources/), compiled recommendations under [wiki/knowledge/recommendations.json](wiki/knowledge/recommendations.json), and historical template references under [wiki/indexes/library.sqlite](wiki/indexes/library.sqlite). Source changes require updating cited recommendation hashes before builds. SQLite is a separately embedded binary asset, never fed to text/model extraction. Validation is not scientific approval.
- Template-reference extraction now belongs in `packages/wiki-sam/src/reference.ts` and `sam.ts`; `src/wiki/file-index/` retains legacy adapters, not a second implementation. Parsers receive the indexer's confined byte snapshot; host code must not import implementation files from portable `skills/` packages. Keep sample pretreatment separate from preparation evacuation; preserve raw historical labType, units, active/inactive state, provenance and sample/device scope. Report calculation whitelists exclude plots/results and retain uncertain parameters as uninterpreted. Changing extraction requires bumping the unified parser version and, when legacy output changes, INDEX_REVISION plus an explicit bundled rebuild with `scripts/export-library.ts`; hash-only reuse must not retain old field coverage.
- The built-in [device-automation skill](skills/device-automation/SKILL.md) is portable, Chinese-language guidance: do not hard-code host-specific tool prefixes or directories into it. It separates preset automation workflows from individual instrument control. `scripts/sam.js profiles/create` uses packaged complete product configurations and normalized task settings to generate new templates without user-provided base files. `scripts/lib/sam-profiles.json` retains source hashes and documented configuration only; `scripts/import-sam-profiles.ts` is an explicit offline importer, never run at startup/chat. Preserve method-specific pressure programs, source version and gas properties; drafts may have pending sample inputs but are not execution-ready. `scripts/automation.js` is simulation-only: submission uses `{deviceId, templateFile}`, commands use `submit-run`/`run`, and state accepts only the current `runs` structure without legacy compatibility. Climber production control uses MCP `get_health/get_status/register_batch/start_batch`; the old script exists only in test fixtures. Registration uses `{batchId,experiments}` and a separate start uses `{batchId}`. Preserve original tube mapping to1..72, batch/experiment identity and unknown-write blocking. Registration uses `ok/data.task`; start accepts only the two documented v1 task envelopes and rejects conflicting identities/states. New configuration has empty `mcpServers/devices`; equipment is explicitly enabled through shared config or the desktop switch, never auto-imported from old script or desktop settings.
- Climber registration `experiments[].samPath` accepts only absolute Windows drive-letter paths to specific `.SAM` files on the manufacturer host. Generated file paths from other hosts require the deployment's Windows drive-path mapping before registration.
- Use `AppError(code, message, status)` from [src/shared/types.ts](src/shared/types.ts) for expected failures; public errors are sanitized. CLI help/replies and JSON listening notifications use stdout; startup/progress/warnings/errors use stderr through [src/shared/console.ts](src/shared/console.ts). Keep JSON stdout machine-readable. Events omit raw script output and full arguments; SSE has no replay and disconnecting a subscriber does not cancel generation.
- File diagnostics belong in `dataDir/logs/agent.jsonl` and `skills.jsonl`, with bounded rotation and credential redaction. Correlate run/execution IDs; never log complete arguments, raw stdout or token streams. Portable skills may emit the optional `[skill-log]` stderr JSON channel; the host persists it to the skill file and keeps it out of command JSON stdout. Persist only bounded sanitized error metadata alongside execution audits, not full process output.
  Desktop run inspection is separate local storage in `run_trace_*` tables: actual LangGraph topology and bounded, credential-redacted model request snapshots. Never send full snapshots through SSE, diagnostic logs or diagnostic exports. Trace reads are session/run-scoped and authenticated; they never replay execution. Desktop opts into stored reasoning with `reasoning=true`; default message/CLI JSON remains unchanged. See [docs/run-inspection.md](docs/run-inspection.md).
- SAM G5 generation follows the operator-confirmed executable 2.11.1/2.11.1.26.1028 schema in the packaged profile, including complete versioned report options, selected reports, empty runtime fields and native extensions. Never set generated `reports` to null; reset known computed caches without deleting options. Keep G12's product/version separate. Preserve source acquisition mode and inactive tables; normalized custom pressure/increment programs select their actual path and T_/D_ options. New task status/UUID replace source runtime identity, and source execution confirmation is not proof that a generated file has passed device acceptance.
- `labType=0` is regular mode and `labType=1` is high-throughput mode. The current manufacturer API supports only regular mode, so current SAM writes require numeric0. Profiles/import/generation must enforce0 regardless of historical source values. Read-only inspection preserves source evidence; modify/save-as normalize inherited nonzero/missing values to0 and report normalizedFields. Explicit nonzero labType in template/changes is rejected before publication; do not call historical mode1 an invalid enum.
- Tests use `bun:test`, `ModelAdapter` doubles, and local HTTP mocks rather than live providers. [tests/helpers.ts](tests/helpers.ts) supplies isolated temporary skill/data directories, disabled bundled assets, and test-only credentials; initialize skill discovery and shut down the service/close storage before fixture cleanup as in [tests/integration/agent.test.ts](tests/integration/agent.test.ts). Keep tests independent of the user's configuration and persistent simulation state.
